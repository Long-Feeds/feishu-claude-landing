Why teams want it

A chat client for your Claude Code — and a scheduler for it.

One daemon holds the sole Feishu connection. Sessions stay bound to their chat, structurally — replies never cross-leak between groups. Everything runs on your own machine.

🧵

Thread = session

Every Feishu thread maps to one Claude session. Reply in an old thread to revive it — same working directory, fresh context.

🗂️

Per-group working dir

Point the “frontend” group at one repo, “data” at another. Each message spawns Claude in the right project automatically.

⏰

Cron agents, from chat

“Every day at 9, check X and post here.” A built-in scheduler creates the job; each run opens a result topic in the target group.

📱

Terminal mirroring

Local claude sessions auto-announce to your default chat and mirror each turn. Reply from your phone to steer.

🛡️

Access control built in

Pairing codes → allowlist → locked. Per-group @-mention rules. A session can only ever reply into its own source chat.

🔒

Self-hosted, no IP

Feishu WebSocket long connection — nothing to expose, no tunnel. Your credentials and code never leave your box.

How it works

Live in your chat in minutes.

Onboarding installs on your own machine (macOS or Linux). Early-access members get a guided setup — and the connect step is collapsing to a single QR scan:

1

Install

Drop the plugin into Claude Code and start the background service (launchd on macOS, systemd on Linux). One command each.

2

Connect Feishu

Link your Feishu bot so the daemon can receive and reply over the WebSocket long connection.

🔜 One-scan setup — device-flow registration mints credentials & scopes from a single QR confirm.
3

Pair & go

DM the bot, pair with a 6-char code, add your groups, and schedule your first agent — all from chat.
